Classificação: assimetria, desbalanceamento e cortes

Nem todo problema de classificação é simétrico. Na prática, os erros têm custos diferentes e as classes raramente são balanceadas.

Assimetria na Função de Perda

Até aqui assumimos que FN e FP têm o mesmo custo (perda 0-1), isto é, a função \(\mathbb{I}(g(\mathbf{x}) \neq Y)\) atribui perda 1 para todo erro cometido. Na prática, os custos são diferentes.

Exemplos:

  • Diagnóstico de câncer: FN (não diagnosticar) é muito mais grave que FP
  • Detecção de default: não detectar um calote custa mais que um falso alarme

Conjuntos desbalanceados

Um dataset é desbalanceado quando uma classe tem muito mais observações que a outra.

  • Exemplos clássicos: fraude, diagnóstico de doenças raras, inadimplência.

Na base Default, a classe Yes representa aproximadamente 3,3% dos dados.

library(ISLR2)
prop.table(table(Default$default))

    No    Yes 
0.9667 0.0333

Problema: um classificador que chama tudo de No tem aproximadamente 97% de acurácia, mas nunca detecta a classe de interesse.

Conjuntos desbalanceados

Classe de interesse: categoria cuja identificação é o principal objetivo do modelo, geralmente representando o evento mais relevante ou raro a ser previsto.

Métricas adequadas:

  • Sensibilidade (recall), especificidade
  • Curva ROC e AUC
  • F1-score, Precision-Recall

Classificação: assimetria, desbalanceamento e cortes

  • Se uma classe é rara, ou seja, \(\mathbb{P}(Y=1\mid\mathbf{x}) << 0.5\) para quase todas as observações, então o classificador de Bayes, \(\mathbb{I}\!\left(\mathbb{P}(Y=1\mid\mathbf{x}) \geq 0.5\right)\),passa a prever sempre \(g(\mathbf{x})=0\) (classificador trivial), minimizando a perda \(\mathbb{P}(g(\mathbf{X}) \neq Y)\).

  • Como os métodos de classificação tendem aproximar o classificador de Bayes, naturalmente irão se aproximar do classificador trivial, neste caso.

Classificação: assimetria, desbalanceamento e cortes

Três abordagens

  1. Função de risco assimétrica:

\[R(g) = \ell_1 P(Y \neq g(\mathbf{x}), Y=0) + \ell_0 P(Y \neq g(\mathbf{x}), Y=1)\]

  • \(\ell_1\) = custo do Falso Positivo
  • \(\ell_0\) = custo do Falso Negativo

Classificação: assimetria, desbalanceamento e cortes

Três abordagens

  1. Função de risco assimétrica:

O classificador de Bayes com perda assimétrica é:

\[g(x) = \mathbb{I}\left(P(Y=1|\mathbf{x}) > \frac{\ell_1}{\ell_0 + \ell_1}\right)\]

  • Cutoff padrão (0,5) é um caso particular quando \(\ell_0 = \ell_1\)
  • Se FN custa 9 vezes mais que FP (\(\ell_0 = 9\), \(\ell_1 = 1\)) → cutoff ótimo = 0,1
  • Definir os custos é um problema de negócio, não estatístico

Três abordagens

  1. Curva ROC (Receiver Operating Characteristic):

A Curva ROC permite avaliar o classificador para todos os limiares de decisão, possibilitando escolher aquele mais adequado aos custos da aplicação.

Representa o compromisso entre

\[ \text{TPR}=\frac{TP}{TP+FN} \qquad\text{e}\qquad \text{FPR}=\frac{FP}{FP+TN}. \]

\[ \mathbb{P}(Y=1\mid\mathbf{x})\ge0.5, \]

escolhe-se um limiar \(\tau\) (threshold), resultando no classificador

\[ g(\mathbf{x})= \mathbb{I}\!\left(\mathbb{P}(Y=1\mid\mathbf{x})\ge\tau\right). \]

Quanto maior o custo do falso negativo, menor tende a ser \(\tau\); quanto maior o custo do falso positivo, maior tende a ser \(\tau\).

Threshold Ótimo pelo Índice de Youden

O Índice de Youden mede a capacidade discriminativa de um classificador para um determinado limiar:

\[ J(\tau)=\text{Sensibilidade}(\tau)+\text{Especificidade}(\tau)-1. \]

O limiar ótimo é aquele que maximiza esse índice:

\[ \tau^{*}=\arg\max_{\tau} J(\tau). \]

Equivalentemente,

\[ \tau^{*}=\arg\max_{\tau} \left[ \text{TPR}(\tau)-\text{FPR}(\tau) \right]. \]

Dataset Shift e Viés de Seleção

Contexto: quando os dados de treino e teste vêm de distribuições diferentes, as premissas do aprendizado de máquina são violadas e o modelo degrada.

Tipos de dataset shift

1. Covariate Shift

A distribuição das variáveis preditoras muda, mas a relação \(P(Y|\mathbf{x})\) permanece a mesma:

\[ P_{\text{treino}}(\mathbf{x}) \neq P_{\text{teste}}(\mathbf{x}) \quad \text{e} \quad P_{\text{treino}}(Y|\mathbf{x}) = P_{\text{teste}}(Y|\mathbf{x}) \]

  • Exemplo: modelo treinado com clientes de SP, aplicado em clientes do RJ
  • Solução: ponderar as observações por \[\beta(\mathbf{x}) = \frac{P_{\text{teste}}(\mathbf{x})}{P_{\text{treino}}(\mathbf{x})}\]

2. Prior Shift

A distribuição da variável resposta muda:

\[ P_{\text{treino}}(Y) \neq P_{\text{teste}}(Y) \quad \text{e} \quad P_{\text{treino}}(\mathbf{x}|Y) = P_{\text{teste}}(\mathbf{x}|Y) \]

  • Exemplo: detector de spam treinado com 50%/50% de spams/hams, aplicado em proporção real 5%/95%
  • Solução: recalibrar as probabilidades usando \[P_{\text{teste}}(Y)\]

3. Viés de Seleção (Selection Bias)

A amostra de treino não é representativa da população por causa de como os dados foram coletados.

  • Exemplo: modelo de risco de crédito treinado apenas com clientes que já foram aprovados em financiamentos anteriores (os rejeitados não aparecem nos dados)

  • Mais difícil de corrigir, requer dados adicionais ou modelagem do mecanismo de seleção

R: Dataset Shift e Viés de Seleção

# Exemplo: correcao de Covariate Shift
# Dados de treino viezados e teste com distribuicao diferente
set.seed(335)

n_treino <- 500
n_teste <- 200

# Treino: X ~ N(0, 1); Teste: X ~ N(1.5, 1)
X_treino <- rnorm(n_treino, 0, 1)
X_teste  <- rnorm(n_teste, 1.5, 1)

# Fator de correcao beta(x) = P_teste(X) / P_treino(X)
# Neste caso: beta(x) = dnorm(x, 1.5, 1) / dnorm(x, 0, 1)
pesos <- dnorm(X_treino, 1.5, 1) / dnorm(X_treino, 0, 1)
summary(pesos)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
 0.0037  0.1113  0.3156  1.1676  0.9503 37.4111

Interpretação

Neste exemplo, os dados de treino e teste são gerados a partir de distribuições diferentes:

  • Treino: \(\mathbf{x} \sim N(0,1)\)
  • Teste: \(\mathbf{x} \sim N(1.5,1)\)

Assim, ocorre Covariate Shift, pois

\[ P_{\text{treino}}(\mathbf{x})\neq P_{\text{teste}}(\mathbf{x}), \]

enquanto a relação entre \(\mathbf{x}\) e \(Y\) é assumida constante.

Para corrigir esse desbalanceamento entre as distribuições, cada observação do conjunto de treino recebe um peso

\[ \beta(\mathbf{x})= \frac{P_{\text{teste}}(\mathbf{x})} {P_{\text{treino}}(\mathbf{x})}. \]

Interpretação dos pesos obtidos

  • Peso próximo de 1: a observação é igualmente representativa nos conjuntos de treino e teste.
  • Peso menor que 1: a observação é mais frequente no treino do que no teste e tem sua influência reduzida.
  • Peso maior que 1: a observação é rara no treino, mas comum no teste, recebendo maior importância durante o treinamento.

Neste exemplo, o peso médio foi 1,17, porém alguns exemplos receberam pesos muito elevados (máximo 37,41), indicando regiões do espaço de atributos pouco representadas no treinamento, mas frequentes na distribuição de teste.

Combinando Classificadores (Stacking / Blending)

Ideia central: em vez de escolher um único modelo, combinar as predições de múltiplos classificadores base para obter um desempenho melhor que qualquer um individualmente.

Arquitetura

  • Nível 0 (base): \(K\) classificadores treinados no dataset original (ex.: logística, árvore, SVM, KNN, etc.)
  • Nível 1 (meta): um meta-classificador treinado para aprender a ponderar as saídas dos modelos base

Problema: se os modelos base forem treinados e suas predições usadas no mesmo dataset, o meta-classificador sofre overfitting.

Combinando Classificadores (Stacking / Blending)

Solução: out-of-fold predictions

  1. Divida os dados em \(V\) folds (ex.: 5)
  2. Para cada fold \(v\):
    • Treine cada modelo base nos \(V-1\) folds restantes
    • Faça predição sobre o fold \(v\) (dados não vistos)
  3. Use as predições out-of-fold de todos os modelos como features para treinar o meta-classificador

Combinando Classificadores (Stacking / Blending)

Combinações comuns

Tipo Meta-classificador Descrição
Blending simples Média/votação Sem meta-modelo, apenas média das probabilidades ou voto majoritário
Stacking linear Regressão logística Aprende pesos lineares para cada modelo base
Stacking não-linear Árvore/Rede Neural Aprende interações complexas entre as predições

Combinando Classificadores (Stacking / Blending)


Ponto importante: o stacking funciona melhor quando os modelos base são diversos. Nestes casos, cometem erros em padrões diferentes, de modo que o meta-classificador consegue aprender qual modelo é mais confiável em cada situação.

R: Stacking / Blending

library(caret)
library(ISLR2)

set.seed(335)

# Modelos base com CV
ctrl <- trainControl(method = "cv", number = 5,
                     savePredictions = "final",
                     classProbs = TRUE)

modelos <- list(
  logistica = train(default ~ balance + student + income,
                    data = Default, method = "glm", trControl = ctrl),
  arvore    = train(default ~ balance + student + income,
                    data = Default, method = "rpart", trControl = ctrl),
  knn       = train(default ~ balance + student + income,
                    data = Default, method = "knn", trControl = ctrl)
)

# Extrair predicoes out-of-fold para cada modelo
preds <- data.frame(
  logistica = modelos$logistica$pred$Yes,
  arvore    = modelos$arvore$pred$Yes,
  knn       = modelos$knn$pred$Yes,
  obs       = modelos$logistica$pred$obs
)

# Meta-classificador: regressao logistica
meta <- train(obs ~ ., data = preds, method = "glm",
              trControl = trainControl(method = "none"))
summary(meta)

Interpretação do Meta-Classificador (Stacking)

O meta-classificador utiliza as probabilidades preditas pelos modelos base (Regressão Logística, Árvore de Decisão e KNN) como variáveis explicativas.

  • O coeficiente da Regressão Logística (\(\beta=9.52\), \(p<0.001\)) é altamente significativo, indicando que suas previsões exercem a maior influência na decisão final do ensemble.

  • Os coeficientes da Árvore de Decisão (\(\beta=-0.53\), \(p=0.508\)) e do KNN (\(\beta=-0.98\), \(p=0.271\)) não são estatisticamente significativos, sugerindo contribuição limitada ao meta-modelo.

Interpretação do Meta-Classificador (Stacking)

  • A redução da Residual Deviance de 2920.6 para 1834.4 indica melhora substancial no ajuste em relação ao modelo nulo.

  • O valor de AIC = 1842.4 reforça que o modelo apresenta um bom compromisso entre qualidade de ajuste e complexidade.

Conclusão: neste conjunto de dados, o stacking baseia sua decisão principalmente nas previsões da Regressão Logística, enquanto Árvore de Decisão e KNN agregam pouca informação adicional ao ensemble.
